# radiod

User-mode host of the `mt792x` chip library on Windows (ADR-0002, option A).

- `hal_win.c`: HAL backend. Registers go through the UMDF proxy (`driver/proxy`); DMA memory is one locked 2 MiB physical block below 4 GiB.
- `out.c`: console output, mirrored with `--live-log <file>` (first argument, before the command) to a file written through to disk line by line (DEBUG messages excluded), so the last line survives a system hang (`docs/FINDINGS.md` F-011). Every command also prints an `interrupt guard:` summary (what the library found in the interrupt enable/status registers).
- `main.c`: bring-up commands.
  - `radiod dma-probe` allocates, checks and frees the DMA block without touching any device.
  - `radiod bringup <stage 1-6> <patch file> <ram file>` runs the staged bring-up of `docs/MT7921-BRINGUP.md` (1 ownership, 2 reset, 3 rings, 4 MCU, 5 firmware, 6 post-boot).
  - `radiod sniff <channel> <seconds> <patch file> <ram file> [--show-ssid] [--hop c1,c2,... --dwell-ms N] [--tune auto|switch|sniffer|both] [--fcs mt76|strip|auto] [--no-hdr-trans] [--no-fwlog] [--drop-fcs-errors] [--debug]`: same preparation as `bringup`, then stage 6, sniffer on that channel, receive for up to 120 s and print a summary (frames/s, 802.11 types, counts by the per-frame channel field, RSSI histogram, transmitters as `OUI:xx:xx:xx` only, AWDL BSSID / AWDL action frames, SSID count and lengths – the SSIDs themselves only with `--show-ssid` –, channel-switch latencies when hopping, all library counters, the first three frames' RXD words and bytes with addresses masked). `RESULT: PASS` when at least one beacon **or AWDL frame** with a good FCS carried the tuned channel in its per-frame channel field (the line says which). Always shuts down. Same hardware rule as `bringup`. Order: read and validate both firmware files, allocate the DMA block, open the proxy, arm the proxy's stop list (`mt792x_stop_ops`, replayed by the proxy when the handle closes) **before** `mt792x_bringup`, run to the requested stage, print `RESULT: PASS/FAIL`, then always `mt792x_shutdown` and close the proxy before the DMA block is freed. **Touches real hardware: only with the maintainer's explicit go-ahead, the proxy bound and the safety checklist of `docs/DEV-SETUP.md` done.**

  - `radiod txtest <channel> <patch file> <ram file> [--count N] [--rate R] [--ssid-len-only] [--show-ssid] [--pair] [--spe-v70] [--wcid-global] [--max-dbm D | --mt76-power] [--no-power-limits] [--debug]`: refuses any channel other than 2.4 GHz 1-13 and 5 GHz 36/40/44/48; bring-up, stage 6, sniffer with TX allowed, then N (default 5, max 20) broadcast probe requests one second apart, each followed by 300 ms of listening for probe responses addressed to our MAC. Prints per probe the TX record, the responses to us, how many had the Retry bit, the responders (`OUI:xx:xx:xx`) and RSSI; then `TX: PASS/FAIL` and `ACK: LIKELY WORKING / NOT WORKING / INCONCLUSIVE` (reasoning in `main.c` and spec 12.8). Always shuts down. **Transmits: only with the maintainer's explicit go-ahead.**

  - `radiod acktest <channel> <patch file> <ram file> [--count N] [--tries T] [--target MAC] [--scan-ms N] [--rate R] [--pair] [--spe-v70] [--wcid-global] [--max-dbm D | --mt76-power] [--no-power-limits] [--debug]`: unicast TX with an ACK request and a TX status report (TXS). Same channel rules and preparation as `txtest`; then listens `--scan-ms` (default 2000) for beacons and picks the BSSID with the best mean RSSI (or `--target`, `aa:bb:cc:dd:ee:ff` or `aa-bb-cc-dd-ee-ff`), and sends N (default 5, max 20) directed probe requests per arm, one per second, alternating between that access point and a *ghost* (a random locally administered address nobody owns), each with `--tries` transmissions allowed (default 15, as mt76). Prints per frame the TX-free status and transmission count, the TXS verdict (ACKed / NOT ACKed / no TXS, raw TXS word 0 and rate) and the probe responses from the target; then `TX: PASS/FAIL` (the access point answered), `TXS: DELIVERED / NOT DELIVERED`, `UNICAST ACK: WORKING / NOT WORKING / CONTRADICTION / INCONCLUSIVE` (WORKING = TXS for >= 80 % of the frames of each arm, >= 80 % of the access point's frames ACKed, every ghost frame NOT ACKed) and `RETRIES: AS REQUESTED / DIFFERENT / UNKNOWN` (ghost frames should use every allowed transmission). Exit code 0 only for `UNICAST ACK: WORKING`. **Transmits: only with the maintainer's explicit go-ahead.**

  - `radiod serve <channel> <patch file> <ram file> [--max-seconds N] [--wait-client S] [--mac chip|random] [--no-filter] [--loopback] [--pair] [--max-dbm D | --mt76-power] [--no-power-limits] [--debug]` (`serve.c`, ADR-0003): the radio server. Creates the message-mode pipe `\\.\pipe\mtdrop-radio` (one instance, SYSTEM + Administrators only) **before** touching the chip, brings the radio up on the channel with TX allowed, waits up to `--wait-client` s (default 60) for one client and speaks the radio link (`radio_link.h`): HELLO; RX frames with a radiotap header built here (TSFT = host QPC clock in µs, FLAGS, RATE or MCS, CHANNEL = the **per-frame** channel, DBM_ANTSIGNAL), filtered to the AWDL BSSID unless `--no-filter`, FCS errors and our own frames dropped; TX with ACK + 15 tries + TX status for unicast, no ACK for group addresses; SET_CHANNEL; STATS; BYE. Ends when the client disconnects, is silent for 5 s (lease), `--max-seconds` (default 120) runs out or the chip reports an error; then the usual orderly shutdown. `--loopback` replaces the chip by a synthetic radio (AWDL PSFs and foreign beacons every 50 ms, unicast TX never ACKed) and touches **no hardware**; only then may interactive users connect, for offline tests. **Transmits: only with the maintainer's explicit go-ahead** (except `--loopback`).
  - `radioctl [--seconds N] [--channel C] [--tx-test] [--connect-timeout S] [--no-filter]` (`radioctl.c`): test client. Retries connecting for `--connect-timeout` s (so it can start first), prints HELLO, counts AWDL action frames (PSF/MIF) and data frames with the radiotap per-frame channel, RSSI and transmitters (OUI only); `--tx-test` (needs `--seconds` >= 10) sends 3 broadcast and 3 ghost-addressed probe requests and checks each TX status. `RX: PASS` = at least one AWDL action frame, every per-frame channel equal to the tuned one. Hardware session: `s3-bringup.ps1 -Commands serve:44:@alt:--max-seconds:60 -Client --seconds:40:--tx-test`.
  - `radio_link_test` (`radio_link_test.c`): unit tests of the protocol encoding and radiotap layout; also builds with GCC (command in the file header).

Needs `SeLockMemoryPrivilege`, so it runs as SYSTEM (`scripts/run-as-system.ps1` + `scripts/radiod-run.ps1` during development; the elevated service later).

Build (MSVC + Ninja, out of tree): `cmake -S driver/radiod -B <build dir> -G Ninja -DCMAKE_BUILD_TYPE=Release && cmake --build <build dir>`.

Known gap: `sleep_us` for waits of 2 ms and more uses `Sleep()`, which rounds up to the system timer tick (measured 14.6 ms for 5.5 ms). Fine for bring-up polling (all library timeouts are elapsed-time based); must be replaced by a high-resolution timer before channel timing matters.
